# 技術架構

狀態：已依此分工建立可玩原型。玩法以 [產品規格](PRODUCT.md) 為準；手機實機與長期平衡驗收仍待進行。

## 1. 技術選擇

| 部分 | 實作方式 |
| --- | --- |
| 語言 | TypeScript |
| 開發與建置 | Vite |
| 戰場 | Phaser：角色、怪物、背景捲動、動畫及特效 |
| 操作介面 | HTML/CSS：背包、待整理區、角色成長、寵物、合成與設定 |
| 遊戲規則 | 與 Phaser、DOM 分離的 TypeScript 邏輯 |
| 保存 | 瀏覽器本機存檔，單一帶版本號的完整快照 |
| 交付 | 同區網開發入口、可靜態部署的建置產物及操作說明 |

首版不設伺服器、登入或雲端同步。精確套件版本鎖定於 `package.json` 與 `package-lock.json`；啟動與建置指令見 [README](../README.md)。

目前程式對應：`src/game/` 管理內容與規則、`src/main.ts` 串接生命週期、`src/clock.ts` 提供前景計時、`src/battle.ts` 繪製 Phaser 戰場、`src/ui.ts` 與 `src/style.css` 管理 HTML 介面、`src/audio.ts` 管理音訊、`src/save.ts` 驗證及保存快照。規則固定每 0.05 秒更新，亂數可於建構引擎時注入。

## 2. 系統責任

- **遊戲狀態與規則：**管理角色、裝備、寵物、背包、樓層、波次、掉落與合成，是能力與獎勵計算的唯一依據。
- **時間推進：**以固定時間步進推進回合動作佇列，依序處理武器、到期輔助及敵方行動，每個動作約 0.5 秒；另處理前進、清波、死亡與重試。畫面幀率不直接決定傷害或收益。
- **畫面：**Phaser 依狀態呈現角色與戰場；HTML/CSS 顯示資料並提交操作。不得各自維護一套物品或戰鬥結果。
- **音訊：**接收攻擊、受擊、掉落、升級、合成及介面操作等事件，播放對應素材，不決定遊戲結果。
- **存檔：**統一保存與還原狀態；讀檔後先維持暫停，等待玩家繼續。

第一版只建立這些實際需要的分工，不預先加入多人、插件或通用遊戲框架。

## 3. 資料與內部介面

| 資料 | 責任 |
| --- | --- |
| 裝備定義 | 品項、占格形狀、能力、回合週期與素材對應 |
| 個別裝備 | 唯一識別、品項、品質及所在位置；背包內另存格子位置與旋轉 |
| 寵物定義 | 物種、攻擊或治療能力、回合週期與素材對應 |
| 個別寵物 | 唯一識別、物種、品質、累積經驗及等級；記錄目前出戰者 |
| 角色與背包 | 等級、經驗、未使用及已分配成長點、當前生命、已解鎖格 |
| 關卡與戰鬥 | 已解鎖樓層、目前樓層與波次、敵人狀態、回合與動作佇列、目前索引、已結算旗標、動作剩餘時間、暫停原因 |
| 戰利品 | 待整理裝備、寵物列表、本次尚未收入的掉落與首次通關獎勵狀態 |
| 設定 | 自動合成開關與最高產出品質、音樂及音效的音量與靜音 |

裝備形狀以占用格子的集合表示，放置檢查依已解鎖格與占用情況判定。背包起始 **4 列 × 5 欄，共 20 格**，最大 **6 列 × 8 欄，共 48 格**；擴充不依賴介面顯示尺寸。

每回合開始建立行動佇列，武器依背包主格位置排序，輔助與敵方接續。動作開始時只結算一次，再保留短暫展示時間；索引及已結算旗標一起保存。整理不重排本回合佇列，新裝備下回合納入，移除者略過。能力由裝備、角色成長與靈寵資料推導，面板以每回合傷害與每三回合治療表示，移除每秒 DPS。

占格、能力計算、經驗升級、合成與容量判斷應可在沒有畫面時測試。亂數作為可控制的輸入，讓測試能指定成功、失敗及掉落結果；不建立對外 API。

## 4. 掉落與合成資料流

1. 擊殺結算經驗與掉落，產生一次完整結果。
2. 寵物蛋轉為個別寵物；先保留尚未收入的結果，再執行已開啟的自動合成與容量判斷。
3. 自動合成只選待整理裝備及未出戰寵物，按低品質至高品質處理，遵守設定的最高產出品質。
4. 成功升階主體，失敗保留原主體，兩種結果都消耗一份材料。寵物保留較高的累積經驗。
5. 仍無空間時記錄待領掉落並暫停，不再產生新戰鬥收益；有空間後收入並續戰。

手動與自動合成共用材料檢查、成功率、消耗與產物結算；自動流程只選待整理裝備。手動可使用背包物品，拖放目標為第一個 ID／主體，維持位置；介面先確認再提交兩個明確 ID。能力改變後限制生命上限，不補血。

## 5. 暫停、音訊與保存

### 前景生命週期

- 整理、容量不足及頁面進入背景皆可停止模擬；保留各自的暫停原因，避免從背景返回時錯誤解除整理或容量暫停。
- 頁面進入背景時保存並暫停戰鬥與音訊，返回時重設時間基準並加入手動暫停，玩家點選繼續後才恢復，不補算背景期間的收益。
- 整理期間不推進回合或動作時間；換裝更新能力時不補滿生命。
- 開始畫面及短轉場是介面暫態，不寫入存檔格式；`ui.isBlocking()` 同時阻止模擬與戰場動畫。Phaser 載入完成後才啟用開始入口，顯示遊戲畫面時重新量測畫布尺寸。
- 管理面板使用原生對話框，開啟時加入整理暫停；關閉時只移除由面板加入的暫停。樓層轉場呈現已完成的規則結果，不再次執行關卡結算。

### 音訊生命週期

- 玩家點選開始遊戲後啟動播放；背景音樂循環播放，音效由實際發生的事件觸發。
- 音樂與音效分別套用音量及靜音設定，不因讀檔或返回前景而重設。
- 進入背景時暫停音訊，返回後依遊戲狀態恢復；不重播暫停期間累積的戰鬥事件。
- 整理時仍可播放介面與合成音效；限制同時播放的音效數量，避免密集戰鬥過度重疊。

### 存檔一致性

- 以 `localStorage` 保存帶版本號的完整快照，包含核心狀態、待領掉落與玩家設定。
- 在配裝、升級分配、合成、掉落結算、關卡變更及設定變更後保存；另於背景切換時保存戰鬥進度。
- 合成材料消耗與結果一起寫入同一份快照；只有完成的結果可保存，不分開寫入材料與產物。
- v2 讀檔還原角色生命、敵人、回合佇列、動作索引與已結算狀態，先保持暫停，不執行離線結算或重複攻擊。
- 盾牌／法杖自然外形改版沿用 v2 格式。載入時保留合法配置，對新占格造成的衝突尋找空位，無法放置者保留在待整理區，滿容量則進待領區並暫停；不消耗物品或重置回合，只有實際重新安置時才提示。
- 首次通關贈蛋狀態與獎勵一起保存，重刷或讀檔不得重複取得保證獎勵。
- 新存檔使用 `evernight-packbound-v2`。讀不到 v2 時可遷移 v1：保留角色成長、物品、靈寵、配置、待領掉落、首通紀錄與設定；秒數冷卻無法直接對應回合，從目前樓層第 1 波滿血重新開始。v1 原文留在舊 key，不覆寫，介面提示遷移結果。
- 另每 5 秒保存戰鬥進度。無法解析或版本不合的存檔會顯示通知，在玩家按開始前不覆寫原資料；瀏覽器拒絕寫入時顯示儲存失敗提示。

## 6. 素材與後續驗證

角色、怪物、靈寵及圖示使用 `generate2dsprite`，背景使用 `generate2dmap`，由內建 image_gen 產生。C 卡通原圖與提示詞在 `assets-source/cartoon-c/`，透明輸出在 `public/assets/`；角色及敵人與背景分離。以 `node scripts/process-art.mjs` 重建、檢查透明邊界；戰場保持 480 × 264 邏輯座標，使用 960 × 528 畫布及平滑縮放，裝備仍等比跨格並隨旋轉轉向。

介面及 Phaser 文字使用網站自帶的 `PackboundRound`（粉圓遊戲字集）。CSS 關閉模擬粗體，開始按鈕等待圖像與字型載入結束；字型失敗時保留系統字體回退。來源與 OFL 在 `public/fonts/`。

音訊由 `scripts/generate-audio.mjs` 另行合成，包含 32 秒循環背景音樂與 9 種事件音效。`src/audio.ts` 將事件名稱對應同名 WAV（換層共用升級音效），同時播放上限為 6 個；背景切換停止尚在播放的音效，避免回到前景補播。

後續驗證涵蓋規則測試、存檔還原、手機觸控、頁面背景切換與音訊恢復。實機結果與桌面模擬分別記錄；完整清單見 [開發路線](../ROADMAP.md)。
