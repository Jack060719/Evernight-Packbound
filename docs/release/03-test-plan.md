## 3. 原子交易、逐擊與中斷

不變量：一個實體 ID 只有一個 owner；集合用 multiset 不先 Set 去重；命令與事件最多提交一次；資源非負合法；物品／寶石／地物守恆。已消耗材料有 receipt，不以消失即視成功。隨機結果、游標、所有權、cursor 同次保存。處理 stale command 的拒絕不消耗 RNG；「合成抽到失敗」是已提交結果，會耗材料與抽樣，不能與驗證拒絕混淆。

### 3.1 持久化故障點

| 點 | 情境 | 必要預期 |
| --- | --- | --- |
| X0 | 開preview、取消、改選目標 | 不抽／不扣／不寫玩家結果；UI自己的選中狀態可變 |

| X2 | 雙擊同command ID；同ID不同payload；不同command仍用舊item version | 至多一次；重入原receipt或拒絕，不執行第二筆 |

| X4 | read／put拋錯、quota、abort、put成功但transaction未complete | 不publish candidate；原子舊狀態；storage阻擋，不將autoRepeatEnabled改false |

所有領取、裝備／寵物合成、重洗、拆解、鑲嵌、拆石、替換、配裝、進關／retry、設定偏好保存都覆蓋成功／拒絕／取消／X1–X6／X9。事件類擊殺／完成另覆蓋 X8；遷移另覆蓋 X7。無確認框的合法命令不用虛構確認，但仍測尚未dispatch取消選擇。

### 3.2 連擊的可恢復邊界（D02／D10，待 G1）

候選以每個直接 impact 加其立即有限後果為一筆原子提交：傷害、獨立暴擊抽樣、有效傷害吸血、同impact立即衍生、反傷、死亡／掉落、hit／target cursor 與 RNG。法杖的直接多目標以 targetOrdinal 區分可恢復 impact；gem 的 sweep／chain 有限 proc 則全部併父 impact 同筆，不在 proc 中間停存，不遞迴。不是整個 weapon action 全回滾，也不能只先存 hitIndex 後存傷害。

測主擊前、第一擊後、最後額外擊前、法杖各直接AoE目標之間、致死／反傷致死／掉落之後的 X3–X5。重載再明確繼續，只執行尚未提交的 impact；不二次 crit／吸血／發獎。英雄死亡停止餘擊；來源拆下同庫存交易保存本輪cancelledSourceIds，重新裝回不補打，新裝下輪。容量與整理只能在完整impact邊界停止，已完成後果不丟；阻擋後仍保留剩餘cursor，真正需取消的條件按D02區分。普通 pause 不可以偽裝成取消整個action恢復攻擊次數。
